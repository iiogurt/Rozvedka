Data exchange

The whole library – database, report files, logos, actor gazetteer and the lists the portal keeps – can be written as a dataset: a few files of at most 2 GB each plus a small manifest, to keep as a backup or to send with any file-transfer service. Someone else imports it instead of crawling the agencies, and either side can crawl on from there. Import first checks every file and compares the dataset with the library: newer, older, mixed, or the same crawl state with reports this library lacks.

Export

python -m rozvedka export /media/usb/rozvedka --name my-label        # everything (about {{ ((files_bytes + 2e8) / 1e9)|round(1) }} GB)
python -m rozvedka export DIR --no-files                            # catalogue only: database, lists, gazetteer
python -m rozvedka export DIR --since 2026-10-01                    # catalogue + only the report files added since
python -m rozvedka export DIR --part-size 500M                      # smaller parts for a stricter transfer service

Send all *.tar.NNN parts and the *.manifest.json. Joined, the parts are an ordinary tar (cat *.tar.* | tar t).

Import

python -m rozvedka import DIR --check                     # verify the parts and compare – changes nothing
python -m rozvedka import DIR                             # restore (empty library) or merge (existing library)
python -m rozvedka import DIR --prefer dataset            # in conflicting hand edits, take the dataset's
  • New installation – the dataset becomes the library; update then crawls on from it (known addresses and files are skipped).
  • Existing library – matched by source key and report address: missing reports, files, text and OCR are added, empty years filled, the later crawl dates kept; conflicting hand edits (hidden, title, language, a year set by hand) are listed and keep this library's value unless --prefer dataset. Reports whose file the dataset does not carry are marked for download.
  • An older dataset adds nothing it does not have; importing the same dataset twice changes nothing.
  • Before any change the database is copied to data/backups/ (the last three are kept); the full report is saved in data/imports/.
